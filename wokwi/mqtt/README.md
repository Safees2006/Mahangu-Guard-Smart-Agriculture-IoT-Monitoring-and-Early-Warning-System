# MQTT version: public Wokwi networking, no private gateway required

The MQTT version is separate from the original HTTP sketch in the parent directory. Use all four files from **this** directory in one ESP32 Arduino Wokwi project. The same virtual circuit is provided here for convenience.

If adding a `config.h` tab is inconvenient, use the [complete single-file version](../mqtt_single_file/README.md) instead. Its `sketch.ino` embeds the public-demo settings and includes the full program; replace the entire Wokwi sketch with that file, rather than replacing it with a configuration-only snippet.

## Laptop

From the project root:

```powershell
.\.venv\Scripts\python.exe mqtt_setup.py
.\.venv\Scripts\python.exe mqtt_bridge.py --public-demo --serve
```

Open **http://127.0.0.1:5050**. Keep the terminal running. Ctrl+C stops the subscriber and this dashboard. `powershell -ExecutionPolicy Bypass -File .\start-mqtt.ps1` runs both setup and startup.

This mode uses `instance/mahangu-mqtt.sqlite3` and **no automatic HTTP feeder**, so the earlier local demo cannot overwrite MQTT samples. The API bearer token stays on the laptop; it is never put in MQTT payloads or this Wokwi sketch. Python dependencies are in the project `.venv`; install `requirements.txt` there on another computer.

`mqtt_setup.py` creates a random exact topic in `instance/mqtt-demo.json` and the matching `wokwi/mqtt/config.h`. Re-running it preserves both files. If you edit a broker or topic manually, match it in both locations; environment overrides to Python do not rewrite the Wokwi file.

## Wokwi

1. Open https://wokwi.com/projects/new/esp32 .
2. Replace `sketch.ino` with **this directory's** `sketch.ino`.
3. Replace `diagram.json` with **this directory's** `diagram.json`.
4. Add `libraries.txt` from this directory: DHT sensor library, Adafruit Unified Sensor and PubSubClient.
5. Add a tab named **config.h**, containing the generated `wokwi/mqtt/config.h`. It contains only the anonymous demo broker and topic, **no local API token**. Do not paste the `config.h.example` placeholder instead.
6. Click ▶. Network-time synchronisation is required before timestamped samples publish. Expect `[MQTT] CONNECTED` and `[MQTT] SENT`, then confirm an accepted record ID in the laptop subscriber and dashboard.

Default: `broker.hivemq.com`, TCP port `1883`, a randomly scoped `mahangu-guard/demo/.../readings` topic. The ESP32 publishes every five seconds, non-retained, QoS 0. The 1,024-byte PubSubClient packet buffer accommodates the JSON payload and topic. The Python subscriber requests QoS 1, but an ESP32 QoS 0 publication still has effective QoS 0; it has no broker receipt guarantee. `[MQTT] SENT` alone does not prove backend storage.

Adjust the first potentiometer for moisture, the second for pH, the third for alkalinity. Click DHT22 to change temperature. Local LED/buzzer checks continue during connection loss, subject to short connection-attempt delays; the device has no offline sample buffer.

## Test without Wokwi

Keep the MQTT dashboard running and use another terminal:

```powershell
.\.venv\Scripts\python.exe mqtt_demo.py --public-demo --scenario dry
.\.venv\Scripts\python.exe mqtt_demo.py --public-demo --scenario heat
.\.venv\Scripts\python.exe mqtt_demo.py --public-demo --scenario normal
```

These are genuine MQTT publications generated by **Python**, explicitly labelled `mqtt_demo`. They verify the broker/subscriber/backend path, not ESP32 execution. The Wokwi firmware labels its own payloads `wokwi_simulation`.

## Security and resilience limits

The public broker is anonymous, shared and unencrypted on port 1883. Anyone can read or publish a known topic. A random topic reduces accidental collisions, **not** unauthorised access. Do not send credentials, personal data or real farm information. Public mode rejects payloads claiming `physical_device`, but synthetic source labels remain self-reported. The authenticated HTTP hop protects the local API from direct unauthorised writes; it does **not** authenticate publishers on the public broker.

The subscriber accepts only the configured exact topic, rejects retained samples and invalid JSON/ranges/device IDs, bounds its in-memory queue, reconnects with backoff, and retries transient local-API failures three times. Duplicate device timestamps return 409 and are skipped. There is no disk queue: samples can be lost during a prolonged outage. Stale/current dashboard text describes sample freshness, not an independent broker-health check.

For a private broker, omit `--public-demo`, configure `MQTT_HOST`, `MQTT_PORT`, `MQTT_TOPIC`, `MQTT_TLS=1`, `MQTT_USERNAME`, `MQTT_PASSWORD` and optionally `MQTT_CA_FILE` in the Python process environment. Private mode requires TLS and credentials. Match the host/port/topic in a private Wokwi `config.h`, set `MQTT_USE_TLS=1`, supply a trusted root CA in `MQTT_ROOT_CA`, and use device-specific broker credentials and topic ACLs. Certificate verification stays enabled. This private-broker setup has not been live-tested in this project.

Python also supports `MQTT_TRANSPORT=websockets` (`/mqtt` path) for brokers that provide it; this does not change the ESP32's TCP transport. Match the broker's documented listener ports.
