# MQTT Setup: Wokwi to Dashboard

This guide connects the Wokwi ESP32 simulation to the Mahangu Guard dashboard through a public MQTT broker. This MQTT route does not require Wokwi's private gateway.

```text
Wokwi ESP32 → HiveMQ broker → local Python subscriber → Flask → SQLite → dashboard
```

## 1. Install the project dependencies

Open a terminal in the project directory. On a new computer, run:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 2. Start the MQTT subscriber and dashboard

Run these commands from the project directory:

```powershell
.\.venv\Scripts\python.exe mqtt_setup.py
.\.venv\Scripts\python.exe mqtt_bridge.py --public-demo --serve
```

Open **http://127.0.0.1:5050** in your browser. Keep the terminal running. Press Ctrl+C to stop the subscriber and dashboard.

On Windows, you can also start both using:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-mqtt.ps1
```

The setup creates `instance/mqtt-demo.json` and a matching `wokwi/mqtt/config.h`. Re-running setup preserves existing settings. MQTT mode uses its own database and does not start the local HTTP demo feeder.

## 3. Configure the Wokwi project

Open an [ESP32 Arduino project](https://wokwi.com/projects/new/esp32) and copy the files from **wokwi/mqtt/** into the corresponding tabs:

| Local file | Wokwi tab |
| --- | --- |
| `wokwi/mqtt/sketch.ino` | `sketch.ino` |
| `wokwi/mqtt/diagram.json` | `diagram.json` |
| `wokwi/mqtt/libraries.txt` | `libraries.txt` |
| `wokwi/mqtt/config.h` generated by setup | `config.h` |

Copy the generated `config.h`, rather than the placeholder `config.h.example`. Keep these MQTT files together; the parent `wokwi/` directory contains a separate direct-HTTP version.

If `libraries.txt` is missing, open Wokwi's Library Manager and add **DHT sensor library**, **Adafruit Unified Sensor** and **PubSubClient**.

If you prefer a sketch without a separate `config.h` tab, follow the [single-file firmware instructions](../wokwi/mqtt_single_file/README.md). Update its `MQTT_TOPIC` to match your local `instance/mqtt-demo.json`.

## 4. Run the simulation and confirm delivery

Click **Start Simulation** in Wokwi. The ESP32 waits for WiFi and network-time synchronisation before publishing timestamped JSON readings.

Check the Serial Monitor for `[MQTT] CONNECTED` and `[MQTT] SENT`. Then check the laptop subscriber for `stored id=...` and compare that sample's timestamp and values with the dashboard history. A SENT message alone does not confirm database storage.

Reduce the moisture control below 30% to try the dry-soil warning. Change the DHT22 temperature to 42°C to try the high-temperature warning. These are demonstration rules, not calibrated agricultural limits.

You can also open the [saved Mahangu Guard simulation](https://wokwi.com/projects/479554649720488961). Its broker and topic must match your laptop settings before readings can arrive.

## 5. Test MQTT without Wokwi

Keep the MQTT subscriber running and open another terminal in the project directory:

```powershell
.\.venv\Scripts\python.exe mqtt_demo.py --public-demo --scenario dry
```

This publishes a **Python-generated MQTT demonstration**. The dashboard labels it `MQTT demo · synthetic`; it does not demonstrate ESP32 execution. Wokwi readings use the `wokwi_simulation` source label.

## 6. Use matching settings on each computer

Each contributor should install the dependencies and run `mqtt_setup.py` locally. A fresh clone generates its own random topic. The laptop subscriber and Wokwi firmware must use the same broker, port, topic and device ID. Local configuration changes do not automatically update a shared Wokwi project.

## 7. Troubleshooting

| Problem | What to check |
| --- | --- |
| Dashboard shows connection refused | Start the subscriber with `--serve`, keep its terminal open and use the configured port, normally 5050. |
| Dashboard opens but has no new readings | Start the simulation and confirm that both sides use matching settings. Check the subscriber output for rejected messages. |
| Serial Monitor says it is waiting for network time | Wait for WiFi and time synchronisation before expecting a published sample. |
| Dashboard shows stale data | Check whether the simulation is still publishing. Samples older than 20 seconds are marked stale. |
| Wokwi build fails after copying settings | Replace the complete `sketch.ino`, including `setup()` and `loop()`, and install all required libraries. |

## 8. Public-broker limits

The public broker is anonymous and unencrypted. Use synthetic readings only. Do not send real farm data, personal information, passwords or the local API token. A random topic is not a password or proof of publisher identity. The HTTP API token stays on the laptop and is not included in MQTT messages.

Physical sensor calibration and long-duration reliability have not been verified. For private-broker configuration and further technical details, see the [MQTT firmware guide](../wokwi/mqtt/README.md).
